# /verify-content — Верификация перевода контента

## Использование

```
/verify-content <game> <version> [file]
```

- `/verify-content daggerheart srd-1.0` — весь перевод (3 агента, 3+ раундов)
- `/verify-content daggerheart srd-1.0 03_System.md` — одна страница (1 агент, fix-цикл)

## Правила проверки

Чеклисты:
- **`.claude/rules/translation-validation.md`** — структура, терминология, оформление, локализация
- **`.claude/rules/translation-quality-review.md`** — редакторская проверка качества (для `verifier-quality`)

Агенты ОБЯЗАНЫ прочитать свои rules файлы перед началом проверки.

## Алгоритм

### Шаг 1: Подготовка

1. Найди EN контент: `src/{game}/{version}/en/**/*.md` (исключая `*_Glossary/`)
2. Найди RU контент: `src/{game}/{version}/ru/**/*.md` (исключая `*_Glossary/`)
3. **Быстрая проверка структуры** — запусти скрипт:
   ```bash
   bash .claude/skills/verify-content/compare_structure.sh src/{game}/{version}/en src/{game}/{version}/ru
   ```
   Если есть расхождения — они будут перечислены. Это экономит время агентов.
3b. **Паритет по длинам сущностей** — запусти:
   ```bash
   node web/scripts/gen-entity-data.mjs   # если API ещё не собран
   python3 .claude/skills/verify-content/verify_ru_en_parity.py --game {game} --version {verKey}
   ```
   Hard-флаги (missing/extra slug) — блокеры; warn-флаги длины — сверить контент
   вручную. Семантика флагов — в docstring скрипта.
4. Построй словарь терминов скриптом (детерминированный парсинг таблиц и логов, лестница приоритетов — см. `.claude/rules/translate-dictionaries.md`):
   ```bash
   python3 .claude/skills/translate-content/build_term_map.py {game} {version}
   ```
   Результат — `/tmp/{game}_{version}_term_map.json`. Верификаторам передаётся **путь к этому JSON**, а не содержимое таблиц.
5. Если RU контент не найден — предложи сначала `/translate-content`
6. Определи режим:
   - `[file]` указан → **режим одной страницы**
   - `[file]` не указан → **режим полной верификации**

### Режим полной верификации (без `[file]`)

#### Шаг 2: Создание команды верификаторов

Создай 3 агента через **Agent** tool (все с **model: "opus"**, `run_in_background: true`):

##### Агент 1: `verifier-terminology`

**Фокус:** Терминологическая точность, количественное соответствие и кросс-версионная консистентность

Проверяет разделы **2. Терминологическое соответствие** + **7. Кросс-версионная консистентность** из `.claude/rules/translation-validation.md`.

##### Агент 2: `verifier-structure`

**Фокус:** Структурная целостность

Проверяет раздел **1. Структурное соответствие** из `.claude/rules/translation-validation.md`.

##### Агент 3: `verifier-quality`

**Фокус:** Качество перевода, оформление и локализация

Проверяет разделы **3. Качество оформления** + **5. Качество локализации** из `.claude/rules/translation-validation.md`.

Дополнительно использует **`.claude/rules/translation-quality-review.md`** как системный промпт — жёсткая редакторская проверка: кальки, канцелярит, тяжеловесность, смысловые смещения, стиль rulebook.

#### Шаг 3: Цикл верификации

Выполни цикл по `.claude/rules/verification-loop.md`.

- **раундов:** 3 (минимум, не ослаблять)
- **режим:** parallel-fanout
- **агенты:** те же 3 Agent-вызова из Шага 2 (terminology / structure / quality)
- **verify-dir:** `src/{game}/{version}/ru/.verify/` — каждый агент пишет находки в `round-{раунд}-{focus}.md` (`focus` = terminology/structure/quality); вызывающая сессия читает только счётчики ошибок и pass/fail
- **при фиксе:** если правка меняет перевод термина → процедура из `.claude/rules/terminology-propagation.md` (dictionary + лог + пропагация); коммит «Верификация контента {game} {version}: раунд {N}»

#### Шаг 4: Отчёт

```
Верификация контента завершена:
- Файлов проверено: K
- Раундов: N
- Исправлений: M
- Статус: ✓ Все проверки пройдены

Детали по раундам:
- Раунд 1: X ошибок терминологии, Y структуры, Z качества → исправлено
- Раунд 2: ...
- Раунд 3: 0 ошибок ✓
```

### Режим одной страницы (с `[file]`)

#### Шаг 2: Запуск верификатора

Запусти 1 opus-агент (`verifier-page`) через **Agent** с **model: "opus"**.

Агент получает:
- EN файл: `src/{game}/{version}/en/{file}`
- RU файл: `src/{game}/{version}/ru/{file}`
- Путь к словарю терминов: `/tmp/{game}_{version}_term_map.json`
- Инструкция: прочитать `.claude/rules/translation-validation.md` и проверить ВСЕ пункты для этой пары файлов

#### Шаг 3: Fix-цикл

```
ПОВТОРЯТЬ:
    1. Агент проверяет пару файлов по ВСЕМУ чеклисту
    2. ЕСЛИ есть ошибки:
       - Исправить все найденные проблемы
       - ПРОДОЛЖИТЬ цикл
    3. ЕСЛИ ошибок нет:
       - ВЫХОД из цикла
```

Коммит НЕ создаётся — вызывающий скилл сам решает когда коммитить.

#### Шаг 4: Отчёт

```
Верификация страницы {file}:
- Итераций: N
- Исправлений: M
- Статус: ✓ / ✗
```

## Терминологические решения

При обнаружении спорного перевода термина — проверь логи в `src/{game}/translate/logs/` и `src/translate/logs/` (общие). Если решение задокументировано — оно имеет приоритет. Новые спорные решения — предложить пользователю и добавить запись в `src/{game}/translate/logs/{date}_log.md`.

При изменении перевода термина — выполнить процедуру из `.claude/rules/terminology-propagation.md`.

## Технические требования

- Большие файлы (>3000 строк) — чтение чанками
- Сообщения коммитов на русском
