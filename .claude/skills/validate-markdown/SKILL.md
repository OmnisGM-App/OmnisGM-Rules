# /validate-markdown — Валидация структуры Markdown

## Использование

```
/validate-markdown <path>
/validate-markdown <path_EN> <path_RU>
```

- `/validate-markdown src/brp/srd-1.0/en/` — проверка одного набора файлов
- `/validate-markdown src/brp/srd-1.0/en/ src/brp/srd-1.0/ru/` — парная проверка EN↔RU

## Назначение

Универсальный структурный валидатор markdown. Используется:
- После **импорта** (`/cleanup-artifacts`) — проверка чистоты EN файлов
- После **перевода** (`/translate-content`) — проверка сохранности структуры EN↔RU
- Самостоятельно — проверка любых markdown файлов

## Алгоритм

### Шаг 1: Детерминированная валидация (скрипт)

Всю детерминированную проверку выполняет `validate_markdown.py` (Python 3, только
stdlib) — не проверяй таблицы/заголовки/форматирование/пробелы/паритет вручную.

```bash
# Один или несколько путей (файлы или директории, рекурсивно):
python3 .claude/skills/validate-markdown/validate_markdown.py src/brp/srd-1.0/en/

# Парная проверка EN↔RU (пары по одинаковому относительному пути; два файла
# спариваются напрямую независимо от имени):
python3 .claude/skills/validate-markdown/validate_markdown.py \
    --pair src/brp/srd-1.0/en/ src/brp/srd-1.0/ru/

# Покрытие индекса глоссария (см. Шаг 2):
python3 .claude/skills/validate-markdown/validate_markdown.py \
    --glossary-index src/.../NN_Spells.md --chapter src/.../07_Spells.md
```

Скрипт покрывает:

- **Таблицы** — равное число колонок во всех строках, наличие разделителя `|---|`
  с тем же числом колонок, разорванные пустой строкой таблицы.
- **Заголовки** — файл начинается с `#`, нет прыжков уровней, пробел после `#`,
  пустая строка перед заголовком, дубли одного уровня подряд.
- **Форматирование** — парность `**`, `*`, `` ` ``; битые ссылки `[text]` без
  `(url)`; пробелы внутри bold-маркеров.
- **Пробелы** — двойные пробелы, trailing whitespace, строки из пробелов, 3+
  пустых строк, `--`/` - ` вместо `—`.
- **Паритет EN↔RU** — число заголовков по уровням, строк таблиц, blockquote,
  элементов списков; расхождение числа строк >5%.
- **Покрытие индекса** — число строк данных в индексе == числу заголовков-сущностей
  в главе (денсивнее из `###`/`####`, как `extract_entities.py`).

**Трактовка вывода.** Каждая строка — `file:line — категория: описание`. В конце —
сводка по категориям и статус. **Exit code 0** — чисто; **1** — найдены проблемы
(используй в CI/pre-commit как признак провала).

### Шаг 2: Покрытие индекса глоссария (авторитетная гарантия)

Для каждого индекса `*_Glossary/NN_Spells.md` (и аналогов — Monsters, MagicItems,
Animals) запусти скрипт с `--glossary-index NN_Spells.md --chapter 07_Spells.md`.
Расхождение числа строк индекса и сущностей в главе — критическая ошибка (частый
регресс — выпавший тир Level 0: кантрипы/заговоры). Это **авторитетная** проверка
против потери сущностей, а не эвристика уровня заголовка в `extract_entities.py`.

### Шаг 3: Семантические проверки (LLM, скрипт не решает)

Скрипт сообщает о структурных фактах, но следующее требует контекста и остаётся
за LLM — прими решение по каждому срабатыванию скрипта и по перечисленному ниже:

- **Разорванные значения таблиц** — строка данных с меньшим числом колонок, где
  ячейка выглядит как продолжение предыдущей (напр. `Material` / `component`).
  Скрипт отметит расхождение колонок; собрать значение обратно — решение LLM (нужен
  контекст). НЕ автофиксится.
- **Неоднозначное незакрытое форматирование** — скрипт ловит нечётность `**`/`*`/
  `` ` ``, но где именно вставить закрывающий маркер, решает LLM.
- **Нарушение иерархии заголовков** — скрипт сообщает прыжок уровня; повысить
  пропущенный заголовок или понизить текущий — решение LLM.
- **Склеенные поля stat-блока** (см. §ниже, `layout_recovery.py` `fix_glued_fields`)
  — разбиение по семантике полей, если требует контекста, остаётся за LLM.

#### Артефакты PDF-конверсии

Дефекты, которые оставляет двухколоночная вёрстка PDF и которые должен был убрать
`/cleanup-artifacts` (см. `.claude/rules/layout-recovery.md`). Канон не должен их содержать.

- **Сырые `<br>`** — ни одного вхождения `<br>`, `<br/>`, `<br />` (регистронезависимо),
  ни в прозе, ни в ячейках таблиц. Каждое — ошибка. Фикс: `layout_recovery.py`
  (`fix_br_artifacts`). Частые следы: разорванное слово (`charac<br>ter`), склейка
  соседних колонок (`7<br>Wis`), перенос в шапке (`Slot<br>Level`).
- **Склеенные поля stat-блока** — строка, начинающаяся с `**Метка:**` и содержащая
  **2+** меток вида `**...:**` (например `**Casting Time:** … **Range:** …`). Каждое
  поле обязано быть на отдельной строке. Фикс: `layout_recovery.py`
  (`fix_glued_fields`).

## Автоисправление (`--fix`)

```
/validate-markdown src/brp/srd-1.0/en/ --fix
```

`validate_markdown.py --fix` применяет только контекстно-независимые правки прямо
в файле:
- Trailing whitespace и строки из пробелов → удалить
- 3+ пустых строк подряд → 2
- `#Заголовок` → `# Заголовок` (пробел после решётки)

Остальное по выводу скрипта правит LLM вручную (нужен контекст):
- Двойные пробелы → одинарные (может быть выравнивание таблицы)
- ` -- ` / ` - ` → ` — ` (легко задеть диапазоны и настоящие дефисы)
- Пустая строка перед заголовком
- Битые таблицы, незакрытое форматирование, нарушение иерархии, расхождения EN↔RU

Коммит после автоисправления:
```
Валидация markdown: автоисправление {path}
```

## Технические требования

- Скрипт — Python 3, только stdlib; читает файлы целиком (память не критична для
  SRD-глав)
- Сообщения коммитов на русском
