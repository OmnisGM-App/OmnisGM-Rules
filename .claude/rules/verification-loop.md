# Цикл верификации (Verification Loop)

Каноничный параметризованный цикл для verify-скиллов. Скилл задаёт параметры
(число раундов, набор агентов, режим, пути), а что именно проверяет каждый
агент — остаётся в скилле.

## Параметры

- **раундов** — минимум чистых проходов (0 ошибок) до выхода. Жёсткий пол, **не ослаблять**.
- **агенты** — набор фокусов; каждый одним вызовом `Agent(subagent_type="general-purpose", description="…", prompt="…", model="opus", run_in_background=true)`.
- **режим** — `parallel-fanout` (несколько агентов, оркестратор собирает сводки) либо `verify+fix-in-agent` (один агент проверяет, правит и коммитит внутри своего контекста).
- **verify-dir** — каталог для отчётов агентов (режим parallel-fanout).

## Режим parallel-fanout

Каждый агент пишет находки в файл `<verify-dir>/round-{раунд}-{focus}.md` (по одному
на фокус). Вызывающая сессия читает из этих файлов **только счётчики ошибок и
сводный pass/fail** — сырые списки в историю сессии не тянутся.

```
раунд = 1
ПОВТОРЯТЬ:
    1. Запустить все Agent-вызовы ПАРАЛЛЕЛЬНО (те же вызовы, что заданы в скилле)
    2. Прочитать сводки из `<verify-dir>/round-{раунд}-*.md`: счётчики ошибок + pass/fail
    3. ЕСЛИ есть ошибки:
       - Исправить все найденные проблемы (скилл-специфичные шаги фикса — см. скилл)
       - Коммит (сообщение на русском), раунд += 1, ПРОДОЛЖИТЬ
    4. ЕСЛИ ошибок нет И раунд >= <раундов>: ВЫХОД ✓
    5. ЕСЛИ ошибок нет И раунд < <раундов>: раунд += 1, ПРОДОЛЖИТЬ
```

Цикл не завершается, пока есть ошибки — даже если раунд уже превысил минимум.

## Режим verify+fix-in-agent

Один агент внутри своего контекста: проверяет → правит → гоняет скрипт-гейт
(branch на exit code) → коммитит → повторяет, пока не наберёт `<раундов>` чистых
проходов. Возвращает вызывающему один финальный статус `✓/✗, N раундов, M правок`.
Оркестратор маршрутизирует один раз; fix-циклы в его историю не попадают. Минимум
раундов держится внутри агента, **не ослаблять**.

## Пауза ручной проверки (после цикла)

Через **AskUserQuestion**:
- Вопрос: «Автоверификация завершена (N раундов, M исправлений). Проверьте файлы в `<путь>` и скажите ОК или внесите правки.»
- Опции: «ОК, продолжаем» / «Внёс правки, перепроверить».

Если «Внёс правки» — прогнать полный цикл заново (тот же минимум раундов) и снова
показать паузу. Повторять, пока не «ОК».
