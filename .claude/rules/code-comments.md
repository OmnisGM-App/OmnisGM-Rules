# Комментарии в коде: жёсткие правила

Копия шаблона из OmnisGM-App/claude-plugins/templates/code-comments.md — править там,
раскатывать копиями. С 2026-09-16 отдельной линзы ревью по комментариям НЕТ (решение
владельца, подтверждено 2026-09-28: вместо линзы — жёстче авторский проход): чистота
комментариев — обязанность автора, проход ниже обязателен перед каждым пушем. Ревью ловит только комментарии, которые врут о поведении или контракте, и
предлагает одно — удалить или починить код, никогда не дописать.

Замер 2026-09-16 (Table): код, написанный сессиями за последние месяцы, несёт 24–36%
строк-комментариев (`sheet domain` 24%, `shared/lib` 33%, новый слайс map-pins 26%,
`firestore.rules` 36%) против 5% в старом `game-items`. Каждая лишняя фраза — кандидат
в находку ревью «комментарий обещает то, чего код не держит», и так рождаются
бесконечные фикс-раунды.

## Что комментарий имеет право говорить

Комментарий отвечает на один вопрос: **почему здесь не очевидное решение**. Если ответ
очевиден из кода, имени или типа — комментария нет.

Разрешено (и только это):

- **Неочевидное ограничение с источником**: номер ишьи, § дока, ссылка на баг библиотеки,
  правило системы (`Rules/…#L…`). Одна–две строки: «`x` в долях 0..1 — переживает смену
  картинки (#375)».
- **Обход внешней ошибки**: что за ошибка, ссылка, при каком условии обход можно снять.
- **Почему не очевидный путь**: «не `useEffect` — пересоздаёт карту при смене языка».
- **Контракт публичного API** — один докблок на экспорт: что принимает, что отдаёт, что
  бросает. Без пересказа сигнатуры.
- **TODO/FIXME только с номером ишьи**: `// TODO(#577): …`. Без номера — не коммитить.

## Что запрещено

1. **Пересказ кода** («увеличиваем счётчик», «если пусто — возвращаем null», «импорт
   хелпера»). Читатель видит код.
2. **Обещания и гарантии**: «единственное место», «гарантирует», «не может произойти»,
   «тест сторожит», «ловит tsc/гейт», «всегда/никогда». Если это правда, её держит тест
   или гейт — назови его именем, а не обещай. Если тест/гейт не держит — обещание ложь.
3. **История и ревью**: «после ревью», «раньше было», «в пятом раунде», «поправлено по
   находке», «в отличие от прежней редакции». Читатель кода истории PR не видит.
   История живёт в git и в PR.
4. **Числа, продублированные из кода или тестов**: «три теста держат», «17 сценариев»,
   «~1.5 мин», «452 файла». Число протухает первым же коммитом. Исключение — число
   и есть причина (порог, лимит, размер буфера) — тогда с источником.
5. **Пересказ правил игры или документа** прозой рядом с кодом, который их реализует.
   Одна ссылка на источник.
6. **Объяснение языка и фреймворка** (как работает `useMemo`, что такое `Record`).
7. **Докстрока, повторяющая сигнатуру** («принимает id и возвращает документ»).
8. **Комментарий-спор с ревью или оправдание** («здесь так, потому что иначе ревью
   находит…»). Спор — в треде PR.
9. **Комментарий вместо имени**: если нужен комментарий, чтобы понять переменную, —
  переименуй переменную.

## Бюджет

- Комментарий у строки — одна строка. Блок над функцией — до трёх строк. Блок длиннее
  трёх строк допустим только для контракта публичного API или обхода внешней ошибки со
  ссылкой; всё, что длиннее, переезжает в `plans/`, в ишью или в док, а в коде остаётся
  одна ссылка.
- Шапка файла — не более пяти строк: назначение модуля и связь (ишья/док). Не журнал
  изменений, не список «что здесь НЕ делаем».
- Ориентир на файл продуктового кода: комментарии ≤10% строк. `firestore.rules` ≤15%.
  Превышение при добавлении нового файла — повод перечитать и вырезать, не повод
  оправдывать.
- Тесты: мотив кейса — в имени теста (`it('…')`), не блоком над ним. Комментарий в тесте
  допустим только для неочевидной подготовки данных.

## Как править по ревью

Ревью нашло ложный или запрещённый комментарий → **удалить** комментарий или **починить
код**, чтобы утверждение стало правдой. Никогда не дописывать оговорку, уточнение,
второй абзац «на самом деле». Две редакции одного объяснения в одном месте хуже, чем ни
одной.

## Проход по комментариям — обязательный шаг перед КАЖДЫМ пушем

Делается после кода и тестов, до тела PR и списка решений. По каждому файлу из
`git diff --name-only <base>...HEAD`:

1. **Перечислить** все комментарии в диффе файла И шапку файла (её дифф мог не тронуть,
   а протухнуть от правки — мог).
2. **Снять** каждый комментарий запрещённого класса (список выше). Не переписывать —
   удалять.
3. **Сверить факты** каждого оставшегося: имена и сигнатуры существуют, числа совпадают с
   кодом, источник (ишья/док/строка правил) назван и верен, условие срабатывания текста
   ошибки равно условию в коде.
4. **Найти близнецов**: фразу, которую изменил, грепни по файлу и соседям — уцелевшая
   вторая редакция объяснения снимается тем же коммитом.
5. **Актуализировать** комментарии, которые эта правка сделала ложью (докстрока над
   изменённой функцией, шапка модуля с перечнем потребителей, «пока не приедет шаг N»),
   — обычно это удаление, реже одна строка с фактом вместо обещания.
6. **Бюджет**: у нового или переписанного файла доля строк-комментариев ≤10% (`rules`
   ≤15%) — считать, а не оценивать; выше — резать до порога.
7. **Грепом, не глазами** (решение владельца 2026-09-28; пересмотр 2026-09-29: за неделю
   62 находки ревью по этому правилу при обязательном шаге — прежний греп давал ложный ноль
   на одном файле без `-H`, не знал регистра, JSX-комментариев, `it.each(`/`test.describe(`,
   не видел числа-пороги, кванторы, ссылки на PR и долю комментариев в новом файле). По
   изменённым файлам прогнать ВСЕ четыре команды и разобрать каждое попадание — снять или
   назвать в строке решений, почему это не нарушение:

   ```bash
   F=$(git diff --name-only <base>...HEAD | grep -vE '\.(png|jpg|webp|svg|lock)$')
   # (а) запрещённые классы 2–4 и 8 + кванторы + ссылки на PR/ревью — регистр не важен, JSX-комментарии тоже
   echo "$F" | xargs grep -HinE '^\s*(//|#|\*|/\*|<!--|\{/\*).*(ревью|раунд|раньше было|поправлен|в отличие от прежн|после правк|исправлен[оа] по|единственн|гарантир|не может произойти|тест сторожит|ловит (tsc|гейт)|\bвсегда\b|\bникогда\b|\bвсе[хм]?\b|\bкажд(ый|ая|ое|ого)\b|\bтолько\b|\breview\b|\bround\b|previously|used to|\bonly\b|\bevery\b|\balways\b|\bnever\b|PR #|#[0-9]{2,4}\b.*(ревью|review))' || true
   # (б) числа с единицами в комментариях — у каждого должен быть исполняемый источник (константа, миксин, useMediaQuery), иначе число врёт
   echo "$F" | xargs grep -HnE '^\s*(//|#|\*|/\*|\{/\*).*[0-9]{2,}\s*(px|ms|s|%|КБ|KB|MB|строк|тестов|файлов)' || true
   # (в) мотив теста блоком над кейсом, в т.ч. через пустую строку и для it.each/test.describe/describe.skip
   echo "$F" | grep -E '\.(test|spec)\.[jt]sx?$' | xargs awk 'BEGIN{n=0} /^\s*(\/\/|\/\*|\*)/{n++; next} /^\s*$/{next} /^\s*(it|test|describe)(\.[a-zA-Z]+)*\(/{if(n) print FILENAME":"FNR; n=0; next} {n=0}' 2>/dev/null || true
   # (г) доля строк-комментариев у каждого нового/переписанного файла (бюджет ≤10 %, rules ≤15 %) — считаем, не оцениваем
   for f in $(echo "$F" | grep -E '\.(ts|tsx|mts|mjs|js|scss|rules)$'); do awk -v f="$f" '/^\s*(\/\/|\*|\/\*|\{\/\*)/{c++} END{if(NR>40 && c*10>NR) printf "%s: %d/%d строк = %d%%\n", f, c, NR, c*100/NR}' "$f"; done
   ```

   Плюс один проход глазами по окну ±20 строк вокруг каждого хунка (`git diff -U20`):
   комментарий, который стал ложью от ЧУЖОЙ правки в том же диффе или от твоей правки в
   соседней строке, стоп-слов не содержит и грепом не ловится. Новый блок кода не встаёт
   между чужим докблоком и тем, что тот описывает: после вставки перечитай соседа сверху
   и снизу.

   Ноль попаданий — норма; попадание с оправданием «это же правда» — не оправдание: правду
   держит тест или гейт, назови его, а комментарий сними.
8. **Одна строка в списке решений** в треде PR: «комментарии: проход по N файлам, снято
   K, актуализировано M, греп-попаданий а/б/в = X/Y/Z (разобраны: …), доля в новых файлах:
   <файл> P %». Без этой строки и без чисел пуш не готов.

Перед пушем прочитай свой дифф глазами читателя без истории PR: каждая фраза в
комментарии либо проверяема по коду рядом, либо удаляется.
