# Типичные ошибки наших PR — правила автору кода

Каждое правило — класс ошибки, который ревью ловило многократно. Перед пушем пройдись списком против своего диффа.
Там, где у правила есть команда, результат команды — число в строке решений PR, а не слово «проверил».

Правила про кадры и прогон Playwright вынесены в `authoring-e2e.md` — он лежит в репах с e2e (Table, News, Rules).
1. **Текстовые близнецы.** Протухает не новое имя, а СТАРАЯ формулировка, которой в диффе нет: снятое понятие («глиф» после удаления поля), прежнее «единственный/только», старое имя варианта, шапка модуля с перечнем потребителей. Самый частый класс (~90 находок за лето, 72 за неделю 22–28.09). Проверка — грепом старого по всей репе с вычетом файлов диффа:
   ```bash
   # токены — из всего диффа, кроме markdown-прозы; близнецов ищем по ВСЕМУ дереву (включая прозу и файлы без расширения), кроме файлов диффа
   git diff -U0 <base>...HEAD -- . ':(exclude)*.md' | grep '^-' | grep -v '^---' | grep -oE '\b[A-Za-z_][A-Za-z0-9_]{3,}\b' | sort -u > /tmp/removed
   git diff -U0 <base>...HEAD -- . ':(exclude)*.md' | grep '^+' | grep -v '^+++' | grep -oE '\b[A-Za-z_][A-Za-z0-9_]{3,}\b' | sort -u > /tmp/added
   comm -23 /tmp/removed /tmp/added > /tmp/gone
   [ -s /tmp/gone ] && git grep -InwFf /tmp/gone -- . ':(exclude)*.tsbuildinfo' ':(exclude)*.csv' $(git diff --name-only <base>...HEAD | sed 's#^#:(exclude,literal)#')
   # слова-уникальности в файлах диффа, которые правка могла сделать ложью
   git diff --name-only --diff-filter=d <base>...HEAD | grep -vE '\.(png|jpg|webp|svg|lock)$' | xargs sh -c 'grep -HinE "$0" "$@" || [ $? -eq 1 ]' 'единственн|только (здесь|тут|в )|всегда|никогда|\bonly\b|\balways\b|\bnever\b'
   ```
   В репе с большим контентом (Rules: SRD под `src/`) добавь к `git grep` pathspec `':(exclude,glob)src/**/*.md'`, иначе поиск тонет в прозе. Русские синонимы снятого понятия (глиф/значок, увеличение/масштаб) допиши в `/tmp/gone` до команды `git grep` — периметр тот же, что у идентификаторов. Каждое попадание — снять тем же коммитом или назвать в строке решений, почему остаётся.
2. **Тест подтверждай мутацией — и назови упавший кейс.** На каждую новую ветку и каждый новый ассерт — три мутанта: «вернуть код до правки», «убрать регистрацию/строку из дефолтного списка», «переставить блок»; красным должен стать ИМЕННО этот тест, ассертом, а не TypeError. В строке решений PR — по строке «мутация: <что сломал> → <имя упавшего кейса>»; ассерт без имени упавшего кейса гейтом не считается. Запрещённые формы, которые выживали неделями: `toContain('--имя-переменной')` и `toBeTruthy()` там, где имя кейса называет значение (сверяется имя, не значение); эталон, импортированный из проверяемого модуля (`const OK = MODULE_CONST` — зелен всегда); ветка под `// Stryker disable`; тест, написанный по рецепту ревью без прогона в обе стороны.
3. **Покрывай ветку-мотив в живой форме — и докажи грепом, что она вообще под тестом.** Сторожи ровно тот вход, ради которого делалась правка, в той форме, в какой он существует в проде (производителей значения найди грепом), а не в удобной для теста. Половина находок недели — не про форму, а про то, что нового просто нет в тестах или оно есть только в e2e, которые CI не гоняет. Проверка:
   ```bash
   # каждый новый testid / экспорт из диффа — двумя колонками: CI-тесты и e2e (вторая колонка покрытием НЕ считается)
   git diff -U0 <base>...HEAD | grep '^+' | grep -oE "data-testid=\"[^\"]+\"|export (default |async )?(const|let|function|class|type|interface|enum) [A-Za-z_]+" | sed -E 's/.*[= ]//; s/"//g' | sort -u | while read n; do printf '%s: ci=%s e2e=%s\n' "$n" "$(git grep -lw "$n" -- '**/__tests__/**' '**/*.test.*' '**/test_*.mjs' '**/test_*.py' | wc -l)" "$(git grep -lw "$n" -- '**/*.spec.*' | wc -l)"; done
   ```
   `ci=0` — находка, не «покрыто соседним тестом». Тест, живущий только в e2e вне CI (колонка `e2e`), покрытием не считается — он идёт в перечень слепых зон п.14.
4. **Тело PR — с финальной головы, с хешем.** Первая строка блока «Проверка/Gate» в теле PR — `git rev-parse --short HEAD`, на котором сняты числа; перед просьбой о мёрже сверь его с `gh pr view N --json headRefOid`. Расхождение — тело переснимается; порядок строго код → прогон → тело, любой пуш после снятия делает блок устаревшим. Чеклист закрывается артефактом (файл в диффе, ссылка), а не словом.
5. **Обе стороны инварианта.** Гейт проверяет и «правильное есть», и «лишнего/подмены нет»; в операциях с путями нормализуй (realpath) и проверяй ОБЕ стороны — источник и назначение.
6. **Отказ — громкий, и в инструментальном коде тоже.** Внешний вызов (fetch/subprocess/файл) проверяет успех или падает с внятным сообщением; NaN/undefined/пустой вход не выключает проверку молча зелёным. Диагностика копит находки списком, а не умирает исключением на полпути, и печатает первопричину один раз; `throw` внутри прохода не стоит раньше записи артефакта и истории. В тестах `test.skip` и ранний `return` по неутверждённому предикату запрещены — это зелёный вместо красного. Для диффа, трогающего `.github/workflows/**` или `scripts/**`: шаг с пайпом — под `shell: bash` (pipefail), `return`/`exit 0` не стоит до проверки кода возврата.
7. **Новый файл — сразу под гейт.** Новый скрипт/модуль сразу включай в tsc/тест-глоб/линт; проверь, что CI-шаг реально исполняется на нужном триггере и ДО критичной операции (деплоя), а не после и не в недостижимых условиях.
8. **Гарантия — кодом, не текстом.** «Не мержить», «read-only», «не пинговать при нуле» — это проверяемое условие в коде/CI; строка комментария или инструкция обходится без единого нарушения.
9. **Чини класс, не вхождение.** Нашёл дефект — грепом добей тот же паттерн по всей репе: соседний файл с тем же флейком/багом — часть твоего же фикса.
10. **Опоры — прогоном, не по памяти.** Каждый факт-довод («X не реализован», «формула считается на месте», счётчики строк/модулей) сверяй с кодом на текущей голове; документ, написанный по памяти о проекте, переписывается после первого же ревью.
11. **Послабления — адресно.** Нормализация/исключение, введённые ради конкретного случая, ограничиваются этим случаем (флаг, версия, пин со счётчиком применений), а не ослабляют гейт для всех данных.
12. **Regex — на вариативность и с границами.** Парсер/регекс гейта прогони на всех реалистичных формах записи одной конструкции (регистр, кавычки, разметка, комментарий в той же строке); ставь границы — `max-age=0` не должен матчить `086400`.
13. **Один источник правды.** Логически связанные значения (список экспортов ⇔ реализация, порог ⇔ докстрока, блок ⇔ имя файла) выводи механически из одного места — два литерала разойдутся при следующей правке.
14. **Назови слепые зоны гейта.** В теле PR явно перечисли классы регрессий, которые зелёный CI НЕ ловит (e2e не в CI, exports/files не проверяются, снапшоты игнорируются) — молчание читается как полное покрытие.
15. **Новый вход — по всем потребителям.** Добавил вариант union, поле общего типа, режим, опцию или проп, сменил кардинальность (одиночка → набор) — грепом перечисли ВСЕХ потребителей типа и все места показа (подписи, печать, экспорт, проекции) и по каждому скажи в теле PR, что с ним стало; «работало на одиночке» — не ответ про набор. Самый крупный непокрытый класс недели (~22 находки; один PR отдал шесть).
16. **Параллельная ветка — те же оговорки; новое — по образцу соседа.** Новая ветка рядом с существующей (выключенный эффект рядом с активным, своя скорость рядом с базовой) наследует ВСЕ фильтры, зажимы и полы соседки — выпиши оговорки соседней ветки списком и проверь каждую на своей. Новый файл, локатор, миграция, форма того же вида — открой соседний и повтори его защиты и поля; расхождение назови в треде осознанным (~17 находок).
17. **Мёртвый остаток и вторая сторона объявления.** Удалил последнего потребителя — снеси проп, экспорт, ключ локали, константу, поле контекста, мок тем же коммитом. Новый экспорт, тип, ключ локали, читаемое поле — грепни вторую сторону (потребителя; у читаемого поля — продового писателя): `git grep <имя>` с одним попаданием-объявлением — находка, «на будущее» не аргумент, юнит с ручной передачей опции второй стороной не считается (~19 находок; один PR отдавал этот класс четыре раунда подряд).
18. **Круговой ход и вырожденный вход.** Форма, открывающая сохранённую запись, возвращает её без изменений: открыл → «Сохранить» без правок → документ побайтно прежний; проверяется юнитом «данные → черновик → сборка → замена», не только путём «новая запись». Пустая строка, `[]`, `{}`, веер в ноль адресов, равные числа — не «заполнено»: ветку выбирай по длине, не по истинности, и прогони каждую новую сборку на вырожденных значениях (~15 находок, две ❗ в одном PR).
19. **Новый интерактив — сценарием, не сборкой.** Кликабельный элемент прогони целиком: повторное нажатие, отказ записи, `disabled` (правило `:disabled` у класса и глобально, мёртвая зона под расширенной областью нажатия), Enter на пустом поле, Esc, стрелки за границу списка, список длиннее окна, колонка уже содержимого, смена языка на лету, соседи в той же флекс-строке. Кадры и юниты этого не видят, если в фикстуре нет такого входа (~13 находок за неделю).
