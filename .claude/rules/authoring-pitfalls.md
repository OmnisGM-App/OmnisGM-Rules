# Common mistakes in our PRs — rules for the code author

<!-- COPY of the shared template: source of truth — OmnisGM-App/claude-plugins/templates/authoring-pitfalls.md;

Each rule is a class of error that review caught repeatedly. Before pushing, walk the list against your diff.
Where a rule has a command, the command's result is a number in the PR decisions line, not the word "checked".

Rules about screenshots and the Playwright run are moved to `authoring-e2e.md`, which lives in the repos with e2e (Table, News, Rules).
1. **Text twins.** What goes stale is not the new name but the OLD wording that is absent from the diff: a removed concept ("glyph" after the field was deleted), a former "the only/single", an old variant name, a module header listing its consumers. The most frequent class (~90 findings over the summer, 72 in the week of 22–28.09). Check: grep the old wording across the whole repo, excluding the diff's files:
   ```bash
   # tokens — from the whole diff except markdown prose; twins are searched across the WHOLE tree (including prose and extensionless files) except the diff files
   git diff -U0 <base>...HEAD -- . ':(exclude)*.md' | grep '^-' | grep -v '^---' | grep -oE '\b[A-Za-z_][A-Za-z0-9_]{3,}\b' | sort -u > /tmp/removed
   git diff -U0 <base>...HEAD -- . ':(exclude)*.md' | grep '^+' | grep -v '^+++' | grep -oE '\b[A-Za-z_][A-Za-z0-9_]{3,}\b' | sort -u > /tmp/added
   comm -23 /tmp/removed /tmp/added > /tmp/gone
   [ -s /tmp/gone ] && git grep -InwFf /tmp/gone -- . ':(exclude)*.tsbuildinfo' ':(exclude)*.csv' $(git diff --name-only <base>...HEAD | sed 's#^#:(exclude,literal)#')
   # uniqueness words in the diff files that the change may have turned into a lie
   git diff --name-only --diff-filter=d <base>...HEAD | grep -vE '\.(png|jpg|webp|svg|lock)$' | xargs sh -c 'grep -HinE "$0" "$@" || [ $? -eq 1 ]' 'единственн|только (здесь|тут|в )|всегда|никогда|\bonly\b|\balways\b|\bnever\b'
   ```
   In a repo with large content (Rules: SRD under `src/`) add the pathspec `':(exclude,glob)src/**/*.md'` to `git grep`, otherwise the search drowns in prose. Add the Russian synonyms of the removed concept (глиф/значок, увеличение/масштаб — glyph/icon, zoom/scale) to `/tmp/gone` before the `git grep` command — the perimeter is the same as for identifiers. Every hit is removed in the same commit or named in the decisions line with the reason it stays.
2. **Confirm the test by mutation — and name the failing case.** For every new branch and every new assert, three mutants: "revert the code to before the change", "remove the registration/line from the default list", "swap the block"; EXACTLY this test must go red, via the assert, not a TypeError. In the PR decisions line, one line each: «мутация: <что сломал> → <имя упавшего кейса>» (mutation: <what was broken> → <name of the failing case>); an assert without the failing case's name does not count as a gate. Forbidden forms that survived for weeks: `toContain('--variable-name')` and `toBeTruthy()` where the case name names the value (the name is checked, not the value); a reference imported from the module under test (`const OK = MODULE_CONST` — always green); a branch under `// Stryker disable`; a test written from the review's recipe without being run both ways.
3. **Cover the motivating branch in its live form — and prove by grep that it is under test at all.** Guard exactly the input the change was made for, in the form it exists in prod (find the value's producers by grep), not in a form convenient for the test. Half of the week's findings were not about form but about the new thing simply being absent from tests, or present only in e2e that CI does not run. Check:
   ```bash
   # каждый новый testid / экспорт из диффа — двумя колонками: CI-тесты и e2e (вторая колонка покрытием НЕ считается)
   git diff -U0 <base>...HEAD | grep '^+' | grep -oE "data-testid=\"[^\"]+\"|export (default |async )?(const|let|function|class|type|interface|enum) [A-Za-z_]+" | sed -E 's/.*[= ]//; s/"//g' | sort -u | while read n; do printf '%s: ci=%s e2e=%s\n' "$n" "$(git grep -lw "$n" -- '**/__tests__/**' '**/*.test.*' '**/test_*.mjs' '**/test_*.py' | wc -l)" "$(git grep -lw "$n" -- '**/*.spec.*' | wc -l)"; done
   ```
   `ci=0` is a finding, not "covered by a neighbouring test". A test living only in e2e outside CI (the `e2e` column) does not count as coverage — it goes into the blind-spot list of rule 14.
4. **PR body — from the final head, with the hash.** The first line of the «Проверка/Gate» (Check/Gate) block in the PR body is `git rev-parse --short HEAD` on which the numbers were taken; before asking for a merge, compare it with `gh pr view N --json headRefOid`. A mismatch means the body is retaken; the order is strictly code → run → body, and any push after the numbers were taken makes the block stale. A checklist item is closed by an artifact (file in the diff, link), not by a word.
5. **Both sides of the invariant.** The gate checks both "the right thing is present" and "nothing extra/substituted"; in path operations normalize (realpath) and check BOTH sides — source and destination.
6. **Failure is loud, in tooling code too.** An external call (fetch/subprocess/file) checks success or fails with a clear message; NaN/undefined/empty input must not silently turn the check green. Diagnostics accumulate findings in a list rather than dying on an exception halfway, and print the root cause once; a `throw` inside a pass must not come before the artifact and history are written. In tests, `test.skip` and an early `return` on an unasserted predicate are forbidden — that is green instead of red. For a diff touching `.github/workflows/**` or `scripts/**`: a step with a pipe runs under `shell: bash` (pipefail), no `return`/`exit 0` before the return code is checked.
7. **A new file goes under the gate immediately.** Include a new script/module in tsc/test glob/lint right away; verify the CI step actually runs on the needed trigger and BEFORE the critical operation (deploy), not after it and not under unreachable conditions.
8. **Guarantee by code, not text.** "Do not merge", "read-only", "do not ping on zero" is a checkable condition in code/CI; a comment line or an instruction gets bypassed without a single violation.
9. **Fix the class, not the occurrence.** Found a defect — grep the same pattern across the whole repo: a neighbouring file with the same flake/bug is part of your own fix.
10. **Anchors by running, not from memory.** Verify every factual argument ("X is not implemented", "the formula is computed in place", line/module counts) against the code at the current head; a document written from memory of the project gets rewritten after the very first review.
11. **Relaxations are targeted.** A normalization/exception introduced for a specific case is limited to that case (flag, version, pin with an application counter) rather than weakening the gate for all data.
12. **Regex — for variability and with boundaries.** Run the gate's parser/regex on all realistic spellings of one construct (case, quotes, markup, a comment on the same line); set boundaries — `max-age=0` must not match `086400`.
13. **One source of truth.** Logically linked values (export list ⇔ implementation, threshold ⇔ docstring, block ⇔ file name) are derived mechanically from one place — two literals will drift apart on the next edit.
14. **Name the gate's blind spots.** In the PR body explicitly list the regression classes that green CI does NOT catch (e2e not in CI, exports/files unchecked, snapshots ignored) — silence reads as full coverage.
15. **New input — across all consumers.** Added a union variant, a field of a shared type, a mode, an option or a prop, changed cardinality (single → set) — grep and list ALL consumers of the type and all display sites (labels, print, export, projections) and for each say in the PR body what happened to it; "worked on the single" is not an answer about the set. The largest uncovered class of the week (~22 findings; one PR yielded six).
16. **A parallel branch — the same caveats; new things follow the neighbour.** A new branch next to an existing one (a disabled effect next to an active one, its own speed next to the base one) inherits ALL filters, clamps and floors of its neighbour — write out the neighbour branch's caveats as a list and check each one on yours. A new file, locator, migration, form of the same kind — open the neighbour and repeat its guards and fields; name any divergence in the thread as deliberate (~17 findings).
17. **Dead remainder and the second side of a declaration.** Removed the last consumer — remove the prop, export, locale key, constant, context field, mock in the same commit. New export, type, locale key, readable field — grep the second side (the consumer; for a readable field, the prod writer): `git grep <name>` with a single hit, the declaration, is a finding, "for the future" is not an argument, a unit test passing the option by hand does not count as the second side (~19 findings; one PR yielded this class four rounds in a row).
18. **Round trip and degenerate input.** A form that opens a saved record returns it unchanged: open → "Save" with no edits → the document is byte-identical; verified by a unit test "data → draft → build → replace", not only via the "new record" path. An empty string, `[]`, `{}`, a fan-out to zero addresses, equal numbers are not "filled in": choose the branch by length, not truthiness, and run every new build on degenerate values (~15 findings, two ❗ in one PR).
19. **New interactive element — by scenario, not by build.** Run a clickable element end to end: repeated press, write rejection, `disabled` (the `:disabled` rule on the class and globally, the dead zone under an enlarged hit area), Enter on an empty field, Esc, arrows past the list edge, a list taller than the window, a column narrower than its content, language switch on the fly, neighbours in the same flex row. Screenshots and unit tests do not see this unless the fixture has such an input (~13 findings in the week).
