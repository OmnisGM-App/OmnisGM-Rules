# Правки контента и переводов — отдельным PR

- Правка markdown-контента и переводов (`src/**`: тексты SRD, RU-переводы, словари `src/dnd/translate/**`) идёт отдельным PR. В PR с кодом (`.github/`, `web/`, `scripts/`, схемы, парсеры) её нет.
- Гейт в PR с кодом нашёл ошибку в контенте → правка уходит в свой контентный PR от `main`. PR с кодом ссылается на него в теле («зависит от #N») и после его мёржа вливает `main` merge-коммитом (без rebase и force-push).
- Исключение: если гейт закрепляет отпечаток или число носителей самого контента (`license_sha` в `PROVENANCE`, пины носителей послаблений из `verify-import-gates.md`), обновление пина идёт в том же контентном PR — иначе ни один из двух PR не зеленеет.
- Пайплайны `import-srd` и `translate-srd` поставляют контент своими фазами (отдельная ветка, squash в `main`) — это и есть отдельная поставка; правило — про ручные правки контента и ошибки контента, найденные гейтом PR с кодом.
- Контентный PR несёт только контент: в теле — что поменялось построчно и чем подтверждено (строка словаря, запись API, страница PDF).
- Заголовок контентного PR — с префиксом `[Content]`.
